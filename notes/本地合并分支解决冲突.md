记录使用git指令将demo分支合并到release分支，并解决冲突的过程。

1. 切换到release分支
假设当前在开发的demo分支，首先切换到release分支并拉取最新代码
```
git checkout release
```
2. 拉取最新的release分支
```
git pull origin release
```
3. 合并demo分支到release分支
```
git merge demo
```
如果存在冲突，git 可能会有提示信息，类似于下面的内容
```
Auto-merging <file>
CONFLICT (content): Merge conflict in <file>
Automatic merge failed; fix conflicts and then commit the result.
```
4. 解决冲突
git会标记冲突文件，使用git status查看冲突文件,冲突的文件会显示为Unmerged paths。

> git status 命令用于查看当前Git 仓库中文件的状态。 它会列出已修改、已暂存、未跟踪等文件的状态信息。


打开冲突文件，找到冲突标记（<<<<<<<，=======，>>>>>>>），手动解决冲突。例如：
```
<<<<<<< HEAD
// release 分支的代码
=======
// dev 分支的代码
>>>>>>> dev
```
你需要决定保留哪一部分代码，或者将两者结合。

解决冲突后，保存文件。
5. 标记冲突已解决
使用git add命令将解决冲突后的文件标记为已解决。
```
git add <file>
```
如果解决了多个冲突文件，可以直接添加所有文件。
```
git add .
```
6. 完成合并
git commit 提交合并结果，git会生成一个默认的合并提交信息，可以直接保存并退出编辑器。

7. 最后将release分支推送到远程仓库
```
git push origin release
```

如果想在合并前备份当前的工作状态（创建一个临时分支）
```
git branch backup-branch
```
