# 跨域是什么
浏览器请求与当前页面不同协议域名端口的资源时，会触发同源策略阻止跨域请求，确保安全性。

换句话说，跨域就是浏览器请求的资源的地址和当前页面的地址中协议域名端口至少有一个不一致。

默认情况不允许ajax访问跨域资源

# 解决跨域的常见方法
## CORS跨域资源共享
服务器设置响应头来允许跨域请求。
```
Access-Control-Allow-Origin: *  // 允许所有域名
Access-Control-Allow-Origin: https://example.com  // 允许特定域名
```
对于复杂请求（如 PUT、DELETE 或带有自定义头的请求），浏览器会先发送一个 OPTIONS 预检请求，服务器需要正确处理。
## JSONP
JSONP利用script标签不受同源策略限制实现跨域请求。

动态创建script标签，请求一个带有回调函数的url，服务器返回的数据会包裹在回调函数中。

但是JSONP只能发送GET请求，且需要服务器支持。
```
function handleResponse(data) {
  console.log(data);
}

const script = document.createElement('script');
script.src = 'https://api.example.com/data?callback=handleResponse';
document.body.appendChild(script);
```

## 代理服务器
通过在同域名下设置一个代理服务器，前端请求代理服务器，代理服务器再请求目标服务器，从而避免跨域问题。

例如，使用 Nginx 或 Node.js 作为代理服务器。

开发环境中，Webpack DevServer 也支持配置代理。
https://www.cnblogs.com/fanzhidongyzby/p/5194895.html     nginx常用代理配置
```
# Nginx 配置示例
location /api/ {
  proxy_pass https://api.example.com/;
}
```
所有访问nginx的请求会被转发到proxy_pass指定的地址

比如Vue3.4.0+的vite，vite.config.ts的config配置代理：
```
    server: {
      port: 3000, // 设置端口为 3000
    },
```
## WebSocket
WebSocket 是一种全双工通信协议，不受同源策略限制，适用于实时通信场景。

## postMessage 
postMessage 是 HTML5 提供的 API，用于在不同窗口或 iframe 之间安全地传递数据。
```
// 发送消息
window.postMessage('Hello', 'https://example.com');

// 接收消息
window.addEventListener('message', (event) => {
  if (event.origin !== 'https://example.com') return;
  console.log(event.data);
});
```
## 修改 document.domain
如果两个页面属于同一顶级域名（如 a.example.com 和 b.example.com），可以通过设置 document.domain 为 example.com 来实现跨域。
```
document.domain = 'example.com';
```


如果是前后端分离项目，推荐使用 CORS。

如果是老项目或需要兼容低版本浏览器，可以使用 JSONP。

如果需要更高的灵活性，可以使用 代理服务器。

“跨域是由于浏览器的同源策略引起的，常见解决方案包括 CORS、JSONP、代理服务器等。CORS 是最推荐的方案，通过服务器设置响应头来允许跨域请求；JSONP 利用 <script> 标签的特性实现跨域，但只支持 GET 请求；代理服务器则是通过中间层转发请求来避免跨域问题。在实际开发中，我会根据项目需求选择合适的方案。”
